# Real-client capture gate — 2026-09-21

`./gradlew :trace-test-harness:clientCaptureTest` starts pinned Paper and Folia
serially through TestServerService. `:benchmarks:clientCaptureEvidence` reruns the
servers and the oracle unit tests and generates a commit-labelled report under
`benchmarks/results/client-capture/`. Neither command reads the private database.

## Implementation and review

The M4 plan proposed an external client runner. The implementation instead starts
an action-only Socket peer inside the harness process, on its own reader thread
with async orchestration. It still connects through loopback TCP, logs in as a
real player, and sends actual interaction packets; it never calls an event or a
server handler directly. Reusing the pinned implementation's packet table and
codecs avoids hardcoded protocol ids and an additional client dependency. The
tradeoff is explicit: this does not independently test the server's wire format,
rendering, registry consumption, online authentication or a retail client.

The client handles login compression, configuration completion, known-pack
negotiation, keepalive/ping, teleport acknowledgement and chunk receipt. Reads
have length and timeout bounds; close terminates and joins the reader. Unsupported
or failed required transitions fail the scenario. The Gradle task checks both
the result and server exit; the first development run exercised that failure path
when the fixture's expected branch was wrong.

Each area uses a new connected player, verifies disconnect, and tests accepted
break and place, cancelled break, an unchanged air break and a later listener's
same-tick placement revert. The initial assumption that air produces no event
was false on pinned Paper: a creative-mode air break fires a natural event and
Trace rejects it at tick end. The gate now requires that exact branch, not merely
absence of a stored row. Folia additionally asserts the two loaded areas belong
to different regions. Fixture world access runs on the owning region; the client
thread has no Bukkit world/player references.

An acknowledgement alone could pass while Trace missed the action. Each action
also has a post-tick world assertion and exact capture-counter deltas. The scan
checks every exposed mutation field: coordinates, material before/after, actor
UUID, cause, kind, exact chunk key, timestamp interval and unique sequence key.
The actor UUID is synthetic, generated by the test account; no real player data
is included. The bounded scan seam is restricted to this scenario and runs async.
It does not expose a new public product API.

ClientCaptureOracleTest challenges missing counters, no exercised capture,
overflow, wrong content/cause/chunk key, missing rows and duplicate identities.
The result collector accepts only named client reports with the final proof
marker and passing oracle tests. Client tasks always execute, so a clean commit's
report cannot silently reuse a dirty development run.

## Limits

This closes the synthetic-event limitation for these exercised creative-mode
block paths. It does not replace the synthetic integration, rollback or crash
gates, and does not prove survival mining, every protection plugin, all block
properties, payloads, containers or all capture causes. MONITOR mutation is an
intentionally adversarial fixture, not recommended plugin behavior. No allocation,
latency or throughput claim follows; these are **not measured** here.

Trace's capture implementation is unchanged. The only production-file addition
is the scenario-restricted read seam. M4 as a whole remains incomplete.

The owner's follow-up selects bounded M4 payload queues after this client gate.
The transport must reject rather than block when full, keep payload ownership
until acknowledgement and persist conservative loss bounds on rejection. It must
not be connected to real capture until atomic event/payload replay exists.
